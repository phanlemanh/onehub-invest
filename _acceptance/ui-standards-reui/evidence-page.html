Vì sao làm

UI của app/ đang lệch nhau và có chỗ tự vẽ tay. Mạnh chốt: dựa hẳn vào luật chính chủ ReUI; thành công = không còn tự vẽ tay, chọn đúng block/component. Phần A dựng máy và luật: skill + MCP ReUI (vendor), skill mỏng onehub-ui, plugin lint onehub-ui có baseline chỉ-giảm, hook Stop + CI, cắm onehub-ui vào hai ổ cắm của kit. Phần B (dọn) đi sau, mỗi đợt một vòng riêng.

Đã hứa
  1. AC-1 — Given repo đã cài installer ReUI, When đọc `.mcp.json` và các file cấu hình agent do installer sinh, Then có server `reui` trỏ `https://mcp.reui.io/api/mcp` và KHÔNG file nào đã commit chứa header `Authorization`, `reui_pat_` hay giá trị `REUI_LICENSE_KEY`.
  2. AC-2 — Given Mạnh đã bỏ entry `reui` phạm vi local và đăng nhập OAuth cho entry dự án, When chạy `claude mcp list` từ gốc repo, Then `reui` ở phạm vi dự án báo Connected.
  3. AC-3 — Given cấu hình lint của `app/`, When lint một file feature mới trong `src/` chứa từng mẫu tự vẽ tay của bảng Task 3 (bảng tay, điều khiển thô, hộp thoại native, màu palette thô cho trạng thái/không cặp dark:, hex cứng, `text-[Npx]`, motion cấm, `asChild`, emoji làm icon, ngoại lệ thiếu lý do), Then mỗi mẫu bị báo đúng luật `onehub-ui/*` tương ứng.
  4. AC-4 — Given cùng cấu hình, When lint mã tuân chuẩn (Badge variant, cặp `text-violet-600 dark:text-violet-400`, `duration-200`, `render` prop, ngoại lệ có lý do) và When lint hex trong một file thuộc danh sách bản đồ, Then KHÔNG có báo cáo `onehub-ui/*` nào (riêng file bản đồ: hex không bị báo nhưng `<table>` vẫn bị báo); và các thư mục vendor `ui/ reui/ blocks/ examples/` không chịu luật `onehub-ui`.
  5. AC-5 — Given baseline `app/eslint-suppressions.json`, When nhánh hiện tại chạy `npm run lint`, Then exit 0; và When một vi phạm mới xuất hiện ở file đã có mục suppress, Then lint đỏ; và When số đếm của một luật trong baseline tăng so với base, Then `check-baseline-growth` exit 1 (đổi tên file giữ nguyên số đếm thì exit 0).
  6. AC-6 — Given hook Stop `.claude/hooks/typecheck-changed.sh`, When agent kết thúc lượt với một file UI vừa đổi chứa vi phạm `onehub-ui`, Then hook exit 2 và in tên luật; When file đó sạch, Then hook exit 0.
  7. AC-7 — Given skill `onehub-ui`, When so `routes.md` với mọi `page.tsx` dưới `app/src/app`, Then hai tập khớp nhau (thiếu hoặc thừa một route thì test đỏ).
  8. AC-8 — Given `_acceptance/config.yaml`, When bộ đọc config của kit giải `feature_loop.ui_standards_skill` và `design_pass.ds_skill`, Then cả hai trả `onehub-ui` và `.claude/skills/onehub-ui/SKILL.md` tồn tại với `name: onehub-ui`.
  9. AC-9 — Given repo sau Phần A, When đọc `AGENTS.md`, `app/CLAUDE.md`, `app/DESIGN_RULES.md`, `.claude/rules/ui.md`, Then mỗi file trỏ tới `onehub-ui` (và AGENTS.md có đúng một khối `reui-agent-rules`), và `invest-portal-ia.md` §3.3 không còn dặn `loading.tsx` cấp segment.
  10. AC-10 — Given `docs/research/ui-baseline-2026-10.md`, When chạy lại `npm run lint:ui-report`, Then tổng vi phạm báo cáo bằng tổng số đếm trong `eslint-suppressions.json` và bằng con số ghi trong tài liệu (số đo "trước" của case study).
